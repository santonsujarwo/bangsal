# QA and Release
1. Read acceptance criteria and identify critical user journeys.
2. Run available type, content, lint, unit, build, and browser checks.
3. Check routes, navigation, forms, images, metadata, canonicals, sitemap, robots, and schema.
4. Check representative mobile, tablet, and desktop layouts.
5. Verify CMS auth and editorial operations in a safe test environment.
6. Record actual command output and unresolved issues.
7. Do not deploy, merge, or push unless explicitly authorized.

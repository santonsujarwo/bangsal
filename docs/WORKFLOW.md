# Development Workflow

## 0 — Repository reconnaissance
Inspect routes, content, scripts, dependencies, redirects, analytics, deployment, and SEO. For migrations, inventory existing URLs before edits. Deliver docs/audit/baseline.md.

## 1 — Business discovery
Collect business identity, industry, offerings, service areas, audience, differentiators, verified proof, conversion goals, contact channels, assets, and languages. Mark unknowns instead of guessing. Deliver docs/project/business-brief.md.

## 2 — Sitemap and content model
Map pages, URL slugs, navigation, collections, relationships, and CTA destinations. Preserve URLs for migrations unless approved. Deliver sitemap and content model.

## 3 — Design direction
Define concept, references, palette, typography, spacing, grid, image direction, components, and responsive rules. Obtain approval before major visual implementation.

## 4 — Foundation
Set up Astro, TypeScript, Tailwind, content schemas, global styles, layouts, navigation, footer, and SEO primitives.

## 5 — Page implementation
Build one representative page first. Validate design system before scaling. Use approved copy and assets.

## 6 — CMS integration
Configure Sveltia collections and file structures. Map editable fields to frontend. Verify auth, read, create, update, publish, media upload, and preview.

## 7 — SEO and accessibility
Implement metadata, canonicals, sitemap, robots, schema, breadcrumbs, alt text, internal links, focus states, form labels, and contrast checks.

## 8 — QA
Run type/content checks, production build, tests, route/link checks, responsive checks, CMS checks, and manual review.

## 9 — Handover
Document setup, CMS authentication, editing, deployment, environment variable names, limitations, and maintenance. Production deployment requires explicit authorization.
